# 忽略 TLS 证书校验设计

## 目标

为 HTTP 请求增加默认关闭的全局开关。启用后，请求会跳过 TLS 证书校验，使证书过期的服务仍可获取响应数据。

## 范围

- 开关名称为“忽略证书校验”，位于应用顶部的现有全局设置区域。
- 开关状态持久化到本地，应用重启后保持用户选择。
- 仅影响 HTTP 请求；WebSocket 与 SSE 的行为不变。
- 开启后跳过全部 TLS 证书校验，而不仅是有效期校验；这同样会接受自签名证书和主机名不匹配的证书。
- 默认关闭，界面通过提示明确其安全风险。

## 数据流

1. `settingsStore` 新增 `ignoreTlsCertificateErrors` 及对应 setter，并与现有设置一同持久化。
2. 应用顶部渲染开关，用户变更时调用 setter。
3. HTTP 发送逻辑读取该设置，传给 `sendHttpRequest`。
4. 前端调用 Tauri 命令时，将布尔值传入 `HttpRequestPayload`。
5. Rust 根据该值配置 `reqwest::Client::builder().danger_accept_invalid_certs(...)`。

## 错误处理与安全性

- 开关关闭时维持严格证书校验，过期或无效证书仍返回请求错误。
- 开关开启时由请求客户端跳过 TLS 证书验证；网络、HTTP 状态码和响应解析仍按现有逻辑处理。
- 提示文案说明该能力仅应用于受信任的调试环境。

## 测试

- 设置 store：默认值为关闭，setter 可修改状态且持久化结构兼容。
- HTTP 前端封装：将开关值序列化至 Tauri 调用参数。
- 应用界面：开关可交互，标签和安全提示可访问。
- Rust：请求载荷能够反序列化该字段，并根据值生成对应客户端配置。
